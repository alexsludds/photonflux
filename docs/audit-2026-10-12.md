# Codebase audit — 12 October 2026 (second pass)

Branch `claude/lucid-dijkstra-nl7lz5`, cut from `origin/main` at `3e33abb`
(#96). A follow-up to [`audit-2026-10.md`](audit-2026-10.md), covering what
landed since (#90–#96) and the open items that audit left.

Scope: `photonflux/`, `webapp/` (backend and frontend), `models/*.va`,
`examples/`, `tests/`. Physics first, then performance, then the browser UI.

**Environment.** A Linux x86-64 cloud container (4 cores, 16 GB):
`circulax 0.2.4`, the pinned bosdi#34 build, the CI-built Linux `openvaf-ir`,
`libngspice` 42 and the pinned SKY130 PDK. **stateye could not be installed**,
so everything that scores TDEC/TDECQ (`test_tdec.py`, `test_eyemeasure.py`,
the Eye tab's Measure button, the TDECQ steps of the example 48/49 flows) is
untested here.

**Baseline** (unmodified `3e33abb`, one pytest process per file): every test
passes except `test_fiber_nl.py`, which the kernel killed at 11 GB of RSS
after 440 s (see *Performance*), and the two stateye files, which skip.

## Fixed

Each physics or behaviour fix ships a test that fails on `3e33abb`.

## Performance

All numbers on the 4-core container, cold JAX caches unless noted.

| Change | Before | After |
|---|---|---|
| `fiber_nl`: the split-step chain ran as an unrolled Python loop, and circulax differentiates a component with one JVP per unknown, so the compiled program grew with the **square** of the segment count. Now one `lax.scan`. | 20 segments (default): 40 s, 2.0 GB. 30: 88 s, 3.9 GB. 60: ~15 GB, OOM (it killed `test_fiber_nl.py`). | 12.9 s, 0.68 GB. 20 s, 0.73 GB. 21 s, 0.98 GB. Identical output (1e-16). |
| Waveguide with real transit (Padé chain), same restructuring. | 3 mm guide (64 stages per direction): 49 s, 1.5 GB | 24 s, 0.76 GB |
| `build_models` re-lowered all 21 Verilog-A models (AST rewrite + exec) and rebuilt every built-in class on each models-cache miss — each new waveform, SKY130 geometry, noise bank or LTI fit, i.e. most optimizer and sweep points — and the first run lowered all of them whatever the circuit used. Built-ins are now built once per process, only the ones a netlist uses, and `cx.va` memoises its loaded modules. (The rest of a first run's ~6 s "models ready" is `import circulax`.) | 0.7 s per miss; ~1 s extra at start-up | ~0 per miss |
| AC/noise linearisation ran un-jitted (op-by-op dispatch). Now one `filter_jit` per structure. | EO AC sweep (example 42_mzm_tw_eo_bw): 18 s cold, 1.35 s warm | 4.2 s cold, 0.03 s warm |
| `cx.attenuator()` / `cx.terminator()` built a new class per call (open structural item 8). | — | cached like the other `cx` components |

Measured but left alone: PRBS generation (13 ms for a PRBS-13Q period,
0.1 s per baked waveform) and the warm transient step (~30 µs for an
11-unknown link) are not bottlenecks. Example 49's transient spends ~22 s of
its 54 s cold run in XLA compilation of the DC and BDF2 programs; see
*Recommendations*.

## UI

- The toolbar no longer pushes **Run** off screen below ~1000 px (the example
  picker shrinks first).
- The eye diagram folds from the skip time, which is not a symbol boundary,
  and measured at a fixed mid-fold phase: on example 10 it reported an eye
  height of **10.9 µW for a 2.46 mW open eye** and drew the eye off-centre. It
  now finds the most open phase, centres the drawing on it and measures there.
- Values are formatted against the base unit: "10.9 µW", not "10.9m mW"
  (eye metrics, stateye results, link-report levels).
- Plot y axes name the quantity ("voltage [V]"): a rotated bare "V" read as a
  chevron.
- The palette's Upload .va button was an unstyled white system button; both
  palette actions now share one dark style. The flow pane's "+ Add step"
  picker no longer truncates.
- An inline favicon (the page 404'd on every load); the optimizer hint lists
  the `tdec:` / `omatdec:` objectives.

## Recommendations (not done here)

1. **TW-laser gain filter.** `tw_seg`/`tw_gain_seg` advance each slice with
   `τ_s dR/dt + R = R_left`, a first-order low-pass of |H|² = 1/(1+(ωτ_s)²).
   Over the ~80 slice passes of a 400 µm cavity round trip that is a ~145 GHz
   wide gain filter centred on the frame, much narrower than a real gain
   bandwidth, so it biases mode competition and SMSR. The box (Preissmann)
   scheme `τ_s/2 (Ṙ + Ṙ_left) + R − R_left = dz/2 [L(R) + L(R_left)]` has exact
   magnitude for a pure delay, but it is non-dissipative: the laser then needs
   an explicit gain-bandwidth model, and the DFB/DBR/FP examples need
   re-validating. Worth doing as its own change.
2. **Compile time of large structures.** The same `lax.scan` restructuring
   applies to the traveling-wave PN shifter (`_pn_phase_shifter_tw`), whose
   ladder and transit chains are unrolled per section; it matters for long
   electrodes (16+ sections with real transit).
3. **CI**: run `pytest` in the built image, one process per file — a single
   process accumulates every compiled program (the baseline run reached 12 GB
   before the OOM killer).
4. Junction nonlinearity in `ring_phase_shifter` (use the abrupt-junction law
   `pn_phase_shifter` already has), one PRBS LFSR, and the remaining
   structural items of the last audit.
5. `CLAUDE.md` describes a different project (Linear issues, `bun run
   build`); there is no JS build here — `node --check webapp/static/*.js`
   plus `pytest` is the equivalent gate.
